# Integrantes y responsabilidades

Máximo tres estudiantes. Completar con datos reales: no se atribuyen contribuciones a personas que no las hicieron.

| Integrante | Usuario GitHub | Responsabilidad propuesta | Contribuciones reales (enlaces a commits/PR) |
|---|---|---|---|
| Por completar | Por completar | Base de datos y servicios backend | Por completar |
| Por completar | Por completar | Interfaz e integración con fetch | Por completar |
| Por completar (si aplica) | Por completar | Pruebas, documentación y sustentación | Por completar |

Cada estudiante debe revisar, entender y poder explicar los cambios de su área. La asistencia para generar código no sustituye los aportes identificables del equipo.

## Trabajo colaborativo sencillo

1. Actualizar la rama principal con `git pull`.
2. Crear una rama por tarea, por ejemplo `git switch -c mejorar-clientes`.
3. Hacer y verificar un cambio concreto.
4. Registrar un commit descriptivo, por ejemplo `git commit -m "Validar correo en formulario de clientes"`.
5. Subir la rama y abrir un pull request para revisión de otro integrante.

No simular autores, fechas ni commits. Registrar decisiones reales y conservar las evidencias de pruebas.
